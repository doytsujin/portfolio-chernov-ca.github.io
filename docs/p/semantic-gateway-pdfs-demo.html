Semantic Gateway for PDFs: every value where it stands on its page

2026 – present · Independent work, unaffiliated with any employer.

Folders of public PDFs served the way an API is: typed fields read by declared rules, each value boxed where its page states it, and the documents as a knowledge graph.

A recording of one session with a running host, on 118 public documents from NIST, FDA and EMA. Declared rules read typed fields, a model fills only what they miss and only with a quote that stands on the page, every value opens where its page states it, the documents form a knowledge graph, and every request passes the same policy gate as the first Semantic Gateway example.

Folders of public PDFs become 3 packs of 118 documents: NIST reference-material certificates, FDA Form 483 inspection forms and EMA medicine overviews. Declared rules read each document's typed fields, and the FDA forms, which are scans, are recognized page by page with OCR. A model fills only what the rules miss, and a value is kept only when its quote stands on the page: 26 values in the FDA pack.

Every value opens where its page states it: 773 of 773 values with text to place are boxed on an image of their page, and a page is served only against the reader's own recorded read, its view logged against that read.

The documents form a knowledge graph built from declared fields, never guessed. 101 entities join each document to what it describes: a reference material by its SRM number, an establishment by its FEI, a medicine by its EMA product number. 14 values are each held by two or more documents, each document is linked to its 3 nearest by the meaning of its text, and 23 declared terms say what the fields mean.

The same gate as the first example governs every view: the auditor is shown each pack's card and the ledger and no document, an agent reaches the same documents over MCP with 12 tools, and a chat answer is shown only if every quote is in a passage returned that turn and every number is in a tool's result. The session holds 96 hash-chained ledger records, all verifying.

People named in the documents appear under aliases, signatures are covered, and the recording serves no PDF file. The page is one recorded session played back in the browser; its numbers are read from the session and checked against it on the served copy.
